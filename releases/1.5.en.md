# HakuX-Mali 1.5 — validation build, code23

[Русский](1.5.ru.md) | [English](1.5.en.md)

Continues unified 1.4/code22. Prepared for RG477M validation; a new GitHub release has not been published. Preserves the RG477M/Rotate Syberia fixes, existing game fixes, MaliSX2 0.2.3, icon, bilingual UI, settings, compact FPS/temperature HUD and the 120 FPS ceiling.

## New picture controls

- **Anisotropic filtering:** original sampling, 2×, 4×, 8× and 16×, bounded by the loaded driver. Supported levels appear after a game starts. Requires restarting the game. Applies to suitable mipmapped 3D colour textures using linear sampling; fonts, video, palettes, point sampling and utility textures retain their original sampling.
- **Movie aspect ratio:** game layout, 4:3, 16:9 or the recognized source ratio. Detection uses Bink metadata in known movie directories and full-screen video overlays, without GPU pixel readback. Unknown movies have a manual pause-menu action and assignable shortcut. Auto does not infer anamorphic ratios or recognize every engine-rendered cutscene; a Bink stream already open when a state is restored may need manual mode.
- **Dynamic resolution:** experimental live changes to actual internal scale, bounded to 1×–2×. Separate range and 30/60/90/120 FPS goal. Changes apply on returning from settings. Adaptation pauses in recognized videos, 2D scenes and measurement calibration. Disabling restores the fixed scale selected for the current launch.

All three features default to off. Global settings, game overrides, portable profiles and RU/EN labels are supported. Changes invalidate the previous measured performance profile; repeat calibration after changing these controls.

## Dynamic resolution behaviour

The controller uses FPS and host-observed time with outstanding graphics work. This is an indirect queue-occupancy estimate including observation latency, **not GPU timestamps or accurate GPU utilization**. G615/MaliSX2 0.2.3 timestamp queries stay disabled; the driver chat confirmed stub implementations in that branch.

After warmup, sustained low FPS can trigger a lower-scale probe. A reduction is retained only when FPS improves by at least 5%; otherwise it rolls back and delays another attempt. An upscale is tried with estimated headroom and retained if it achieves at least 95% of the requested goal. The goal cannot remove a game's own frame cap. Unsupported formats, allocation or preparation failures retain the old images and stop further automatic transitions until the game restarts.

Colour, depth, stencil and mip/layer surfaces are preserved at a frame boundary after prior work completes. G615 lacks depth/stencil `BLIT_DST`; a tested GPU-buffer/compute path handles these copies. The installed driver is unchanged. Transitions need temporary memory and can cause a short hitch; this is not seamless per-frame scaling.

## Validation scope

RG477M: real 8×/16× samplers, manual aspect switching, automatic entry/exit around Warrior Within videos. Syberia live scale changes in both directions took about 62–68 ms; the observed scene increased from roughly 45–49 FPS at 2× to 57–59 FPS at 1×. These are local observations, not a general speedup claim for every game.

The GPU probe covers 8 colour/depth/stencil formats, sizes 16/25, mip0/1 and layer1: 32 cases with an independent intermediate 2× oracle and roundtrip checks. All defined values matched; undefined D24 padding is excluded. This does not validate all AFBC variants or every game's stencil effects. New controls were not tested on RG Vita Pro or RG Rotate in this session.

Install over the existing app to retain data. Package ID and signing certificate are unchanged; do not uninstall first.
