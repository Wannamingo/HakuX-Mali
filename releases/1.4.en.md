# HakuX-Mali 1.4 — one release for three handhelds

[Русский](1.4.ru.md) | [English](1.4.en.md)

One APK for **ANBERNIC RG477M, RG Vita Pro and RG Rotate**. Version **1.4**, versionCode **22**, Android **arm64-v8a**, based on hakuX 1.2.0. This release combines the established 1.2 interface with the new 1.3–1.4 settings, measured performance calibration and the extended Syberia menu fix for RG Rotate. No separate device APK is required.

## Main addition: measured performance calibration

In a stable gameplay scene, open the pause menu → **Calibrate performance**. The emulator creates a separate temporary checkpoint and starts several configurations from that same state in fresh native processes:

- 1×, Bilinear, FXAA Off;
- the current manual configuration;
- 2×, Bilinear, FXAA Off;
- 1×, GSR, FXAA Off;
- a repeat of the first configuration to check whether conditions changed.

Duplicate configurations are combined. Each trial warms up for 10 seconds. The first measurement lasts 15 seconds; subsequent measurements last 10 seconds each. All candidates share a display-aware FPS ceiling of at most 120. Gameplay controls are blocked during comparison; Back/B cancels and starts recovery.

Selection uses actual FPS and frame intervals. Candidates within 3% of the best FPS are compared by P95 frame time, then lower graphics workload. If the reference repeat differs by more than 10% in FPS or 25% in P95, no new profile is offered. This avoids storing a result affected by changing conditions.

Results include FPS, frame intervals, process CPU time, peak process RSS and available temperatures. GPU timing is shown only when supported and allowed by existing driver workarounds. “Unavailable” does not mean zero GPU load. The existing Mali-G615 `NO_TIMESTAMPS` workaround remains enabled.

**Apply result and enable Auto for this game** stores a game-specific measured profile. It is tied to the game, device, driver and emulator version; environment changes require a new measurement. Cancellation, backgrounding or a crash does not count as a successful trial. Recovery to the original checkpoint is available. Temporary state data is separate from user slots and removed after successful recovery.

Calibration evaluates the chosen scene, not the entire game. It does not change CPU/GPU clocks, drivers, game timing, audio or compatibility fixes. Dynamic resolution and automatic cutscene aspect detection are not part of this release. [Method and limits](../docs/MEASURED-CALIBRATION.en.md).

## Automatic settings switch

Available at the top of **Graphics**, globally and per game. It is off by default. A game can inherit the global option or override it.

When no valid measured profile exists, an explicitly identified starting configuration is used: 1×, FXAA Off, Bilinear, with a display-aware ceiling up to 120 FPS. The app offers calibration. Manual scale, filter, FXAA and FPS values are preserved; disabling Auto restores them on the next game start. This initial configuration is not itself a benchmark result.

A new **Economy** profile selects 1×, FXAA Off, Bilinear and 30 FPS on the next launch. It can reduce workload; battery life was not separately benchmarked.

## Audio

- Independent game volume and mute, applied when returning to the game.
- **Low latency**, **Balanced** and **Stability** buffering choices.
- **Spatial audio (HRTF)** toggle.

Buffering and HRTF apply on the next launch. Smaller buffers may crackle under heavy load. Defaults preserve the previous behaviour: 100% volume, unmuted, Balanced buffering, HRTF enabled. Settings are available globally and per game.

## Framing and display

Independent crop on each edge, 100–200% zoom, horizontal/vertical positioning and a reset button adjust the visible picture. These apply on resume; cropping does not increase rendering resolution. The existing 4:3 and 16:9 choices remain. Display refresh can use a supported mode at the current resolution, or follow the system.

Brightness, contrast, saturation, gamma, colour temperature and sharpness are retained, along with FXAA and Bilinear / GSR scaling. Render scale and graphics presets apply on the next game launch. The 120 FPS upper bound preserves a game's own lower 30/60 FPS limit.

## Saves, resume and shortcuts

- Optional automatic state saving on **normal game exit**, with an optional resume prompt when launching from the library.
- Separate manual slots 1–10, automatic slot 0 and quick slot 11. Calibration uses its own temporary directory.
- Failed automatic saves retain the previous state and offer to leave without a new save, avoiding an indefinitely blocked exit.
- User-assigned **Select + gamepad button** shortcuts for pause, screenshots, quick save/load and save/load menus. An ordinary Select press retains its game function.
- Game screenshots are stored in **Pictures/HakuX-Mali** on the checked Android versions.

Automatic saving cannot run after a crash, force stop or power loss. States depend on core and game-version compatibility.

## Controls and portable settings

Added left/right stick sensitivity, per-axis inversion and rumble strength. Existing dead zones, button mapping and controller profiles remain.

Global or per-game settings can be exported and imported into another scope. Import validates the format and value ranges before replacing the target settings. Games, savestates, drivers, folder-access grants and controller profiles are excluded. Measured device-specific results are not transferred between handhelds.

## Temperatures and HUD

The HUD remains **one row**: FPS, average/last frame time and selected available CPU/SoC, GPU and battery temperatures. Size, corner, background and individual readings can be configured. Rotate exposed battery temperature in the current check; this is not a GPU or CPU temperature measurement.

Optional warnings use separate CPU/SoC and battery thresholds. They do not control clocks or disable Android thermal protection. Calibration stops at a severe Android thermal status or the configured battery threshold. Check the passively cooled Vita Pro over a longer session at your chosen settings.

## Interface

Russian, English and system language; categorized settings; search that jumps to a setting; global/per-game overrides; graphics presets; library grid/list and cover sizing are retained. New audio, display, thermal and automatic options are integrated into their categories. Search also includes gamepad shortcuts. [Release gallery](../docs/screenshots/1.4/README.md) and [main interface gallery from 1.2](../docs/screenshots/1.2/README.md).

## Syberia on RG Rotate

The existing Syberia menu-background fix now also covers imported shared RAM. An extra whole-target upload at an idle boundary could restore an old frame; the previous condition excluded it only with copied RAM. Normal synchronization points remain, and the title-specific condition leaves other games unchanged.

The final APK was checked on Rotate with its system Mali-G52 / Vulkan 1.1 driver and `zero_copy=1`: normal menu startup, complete background, entering options and returning without the stale image. Checked menu frames were around 60 FPS. Forced copied RAM and temporary diagnostic properties are not required.

## Serious Sam launcher workaround

The **T-Rus Ryudo** folder package can hang in an added menu/trainer before the real game starts. Preserve the original `default.xbe` under a backup name, then **copy `eng.xbe` as `default.xbe`**, keeping the original `eng.xbe` and all resources. [Step-by-step instructions and undo](../docs/SERIOUS-SAM.en.md).

On Rotate, the same package reached a rendered gameplay level; the checked frame showed 60 FPS. **The owner confirmed that Russian voice audio was preserved after this workaround.** This applies to the checked package and its resources; Russian text was not separately verified. The emulator does not automatically rename game files, and no game executables are included in the APK.

Select your own ISO/XISO directory or game folders containing `default.xbe`. Updating preserves manual settings; Auto is off by default. The built-in update source is **Wannamingo/HakuX-Mali**. ES-DE retains Microsoft Xbox → HakuX-Mali (Standalone) launching through [our configurations](https://github.com/Wannamingo/es-de-android-custom-systems).

Bundled MaliSX2, icons and other native libraries are preserved. The final extension changes only Syberia's idle-upload policy; FEX was not modified.

Assets include complete source with used dependency snapshots and licences, revision manifest, patch, RU/EN notes, reports and SHA256SUMS. Games, BIOS, HDD images, user states and private signing keys are excluded. GPLv3+; upstream: [rfandango/hakuX](https://github.com/rfandango/hakuX).
