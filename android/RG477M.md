# RG477M / MaliSX2 (experimental)

This source adaptation targets ANBERNIC RG477M, Android 14, arm64,
Mali-G615 MC6 / Dimensity 8300 (MT6897), with MaliSX2 0.2.3. The current source base is hakuX 1.2.0.
The native core and Android APK are built from these sources.

## Bundled-driver build 1.2.0-rg477m.2

The built-in official driver archive is checksum-verified and selected on a
fresh RG477M/MT6897 installation. Existing explicit driver choices are retained;
an identical imported MaliSX2 binary is migrated once. The new supported-device
policy also recognizes Dimensity 8300 and 8300 Ultra identifiers with API 29+,
arm64 and `/dev/mali0`. Other MT6897 products are not individually tested.
The fresh frame limit is 120 FPS. Updates query the fork and verify the exact
installed package ID and signer. Both aspect ratios were selected through the
actual UI and verified against Vulkan viewport logs. See the
[English](../releases/1.2.0-rg477m.2.en.md) /
[Russian](../releases/1.2.0-rg477m.2.ru.md) build notes and validation scope.

## Updating the base to 1.2.0

`1.2.0-rg477m.1` (version code 9) includes upstream 1.2.0 game, audio,
memory, controller and networking changes. The RG477M MaliSX2 driver policy,
fence completion/presentation, XBE file-media handling, guest SEH/REP MOVS,
visibility results, video texture selection, vertex alignment, exact texture
bounds and ROP pass splitting are retained. The supplied launcher artwork,
FPS limiter and single-line release HUD are retained.

The upstream memory fix supersedes the local Ultimate Spider-Man fix; its
MM v2 serialized fields match the previous adaptation. Driver quirk bits are
distinct (`present_cpu_wait` at bit 11, `rop_pass_split` at bit 12). The FPS
argument is handled by 1.2.0's shared core option parser. MaliSX2 still uses
fences and waits for presentation completion; Turnip keeps the new GPU-wait
path. The Turnip overlay pacing does not delay overlays on Mali.

Apply `tools/native/adrenotools-kgsl-context-priority.patch` to the pinned
adrenotools checkout before building, as required by upstream 1.2.0. Rebuild
and package all five hook libraries, including `libkgsl_context_hook.so`;
these hooks share a private ABI and must come from the same build. The KGSL
priority feature is selected only for Mesa/Turnip, not for MaliSX2.

## What changes

- The driver selector is enabled for an arm64, API 29+ RG477M exposing
  `/dev/mali0`. Model, device and product identifiers are checked, including
  `ro.product.vendor.model` on GammaOS/GSI builds. Dimensity 8300/8300 Ultra (MT6897) identifiers are also accepted by .2; other
  Mali families are not enabled by this policy.
- RG477M accepts the MaliSX2 library name `libvulkan_malisx2.so` only.
  Turnip packages are rejected there; MaliSX2 is rejected on Adreno.
  The package's library name must be a basename, with no paths or separators.
  These are compatibility checks, not authentication of the library's contents.
- The existing adrenotools **custom driver** mode loads the Android Vulkan
  loader and substitutes its HAL. No KGSL memory-import mode or direct ICD
  loading is used. Android still supplies surface and swapchain support.
- MaliSX2 0.2.3 has Vulkan 1.1 and no timeline semaphores. hakuX now tracks
  render completion with an ordered, bounded queue of 64 reusable Vulkan
  fences on devices without that feature. The watcher publishes completion
  only after the fence signals and readbacks land. CPU waiters do not touch
  recycled fences. Queue saturation applies back pressure; GPU loss wakes
  both producers and waiters. Existing timeline-capable devices keep their path.
- The window presenter also uses one reusable Vulkan fence per frame on
  devices without timelines. It waits before reusing command pools and
  descriptor/UBO storage, and before presenting without a wait semaphore.
  A failed fence wait stops presentation rather than exposing unfinished
  image writes to Android. Timeline-capable devices retain their semaphore.
- Device creation no longer requests timeline features/extensions when absent;
  legacy submits omit the timeline pNext in fence mode. Instance API requests
  are bounded by the loader's version; device API use is bounded by the instance.
- Existing hakuX fallbacks handle render passes, synchronization 1.0, fixed
  descriptor sets, BC texture expansion and static pipeline state. The existing
  Mali quirks remain enabled. No unsupported feature is falsely advertised.
- Selecting MaliSX2 requires `driverInfo` to contain `malisx2` after physical
  device enumeration. A silent adrenotools fallback to the stock driver is
  reported as an error. Failure to open the loader is also explicit.

## Build and install

### File-backed media startup

The XBE loader clears only bit 0 of `SecurityFlags` in the in-memory
certificate when the complete field is declared and lies within the loaded
headers. This tells XAPI not to require the physical DVD's signed security
descriptor from a file-backed image. It fixes an early return to firmware
seen in Syberia, Ultimate Beach Soccer, Rayman 3, The Sands of Time and XGRA.
It applies by certificate flags, without a title list or game-code patches.
The ISO, other certificate bits, title IDs and the SHA/RSA routines are
unchanged. Old and malformed certificates are left alone. This follows the
runtime media policy used by
[Cxbx-Reloaded](https://github.com/Cxbx-Reloaded/Cxbx-Reloaded/blob/585c49a50af1255ab155099e06f24505f9c5a800/src/core/kernel/init/KrnlPatches.hpp).
It does not implement raw physical-drive authentication or resolve unrelated
memory faults and missing kernel services.

The host regression test compiles the production policy module:

```sh
cmake -S tests/native/xbe_media -B build/xbe-media-host
cmake --build build/xbe-media-host --config Debug
ctest --test-dir build/xbe-media-host -C Debug --output-on-failure
```

### Memory exceptions and allocation attributes

Serious Sam's stream pager reserves a file-sized virtual buffer and commits
its pages in an access-violation filter. When the title has no IDT page-fault
handler, the native kernel now delivers a first-chance access violation to
its valid SEH chain, with the fault address, read/write direction and original
instruction/stack. The existing title-owned IDT handler still takes precedence.

FEX's non-atomic REP MOVS loop keeps partial progress in scratch pointers.
Before delivering an exception, the embedding recovers ESI/EDI/ECX from its
faulting scalar or vector access, including reverse copies and accesses that
straddle a page. Otherwise the pager repeatedly evicts and reloads the same
pages as the whole copy restarts. This change is outside the FEX submodule.

Ultimate Spider-Man identifies contiguous GPU allocations by the
PAGE_WRITECOMBINE bit returned from MmQueryAddressProtect. Contiguous and
system allocations now retain their requested protection/cache attributes,
including queries inside a block. Losing that bit previously sent physical
allocations to the CRT heap's free routine. MM savestates use section v2;
v1 remains readable with the previous PAGE_READWRITE default.

### Visibility without GPU queries

MaliSX2 0.2.3 on RG477M does not provide the query backend used here. Reports
with no measured samples must not be reported as occluded. Unknown results
now conservatively report visible, including reports without intervening draws,
failed query parts, pool creation failures and pending-report overflow. A
completed, supported zero-sample query remains zero. This is a renderer-wide
fallback, without a game list. It can draw additional hidden objects and cannot
provide accurate visibility-dependent effects on a backend without queries.

An on-device A/B test of one stationary Serious Sam scene reproduced black
flickering patches with fabricated zeros and removed them with visible reports.
The fallback is built in; debug properties are not needed for normal use.

Host checks for these paths:

```sh
cmake -S tests/native/seh -B build/seh-host
cmake --build build/seh-host --config Debug
ctest --test-dir build/seh-host -C Debug --output-on-failure
cmake -S tests/native/rep_fault -B build/rep-host
cmake --build build/rep-host --config Debug
ctest --test-dir build/rep-host -C Debug --output-on-failure
cmake -S tests/native/visibility -B build/visibility-host
cmake --build build/visibility-host --config Debug
ctest --test-dir build/visibility-host -C Debug --output-on-failure
python3 tools/native/statelock.py
```

### Linear video textures over render targets

Warrior Within reuses one address for a 640x480, 2560-byte-pitch colour
buffer and a 320x240, 1280-byte-pitch postprocess target. Selecting only by
the last render-target bind chose the smaller image for a full-size Bink
movie: the frame showed horizontal stripes and its bottom half repeated
the final sampled row. Linear texture lookup now prefers a surface with
the requested pitch, texel size and sufficient dimensions before comparing
bind recency. Swizzled views and cases without a compatible linear target
retain the previous recency rule. There is no per-title patch.

The policy regression test reproduces the full/half-size alias and covers
reverse lookup, equal-layout recency, undersized/wrong-pitch/wrong-texel
targets, subrectangles and the unchanged swizzled fallback:

```sh
cmake -S tests/native/tex_view -B build/tex-view-host
cmake --build build/tex-view-host --config Debug
ctest --test-dir build/tex-view-host -C Debug --output-on-failure
```

### Unaligned vertex arrays

The Two Thrones uses 50-byte character vertices. Float weights and texture
coordinates occur at two-byte offsets and every other position is unaligned.
Ordinary Vulkan vertex input requires natural component alignment. The array
path now detects such bindings and copies their attributes into aligned slots
before submitting the draw, retaining raw values and the original indices.
The observed character layout becomes 52 bytes per vertex. Aligned bindings
retain the existing direct/copy path; this is not a title-specific override.

The host test checks exact attribute bytes for odd-stride vertices, alignment,
short/byte fallback padding, constant attributes, binding isolation and bounds:

```sh
cmake -S tests/native/vertex_repack -B build/vertex-repack-host
cmake --build build/vertex-repack-host --config Debug
ctest --test-dir build/vertex-repack-host -C Debug --output-on-failure
```

### Exact bounds of linear texture views

Sands of Time blurs 40x30, 20x15 and 10x7 textures stored in rows padded to
48, 32 and 16 pixels. Sampling the entire render-target image exposes the
padding to blur taps instead of applying the texture's requested border.
Captured targets contained green padding that became a bright vertical band
on the right side of the final frame.

Linear colour views that fit inside a larger target now sample an exact-size
GPU copy. Copies are cached by layout and refreshed only after their source
changes. They do not become guest-memory writers or participate in target
selection. Render targets retain their original size and contents. The user
confirmed that the green band disappeared on RG477M. The texture-view host
test covers all three padded widths, height cropping and unchanged exact,
swizzled, incompatible and invalid views.

### MaliSX2 ROP transitions

On MaliSX2 0.2.3, changing blend enable or the colour write mask within one
legacy pass corrupts transparent layers. Sands of Time showed flickering
black blocks in the sky and on the floor. Original and decoded texture data
were correct; disabling the depth test did not remove the blocks. A/B tests
removed them by splitting every draw, and also by splitting only these two
ROP transitions. The latter retains runs of identical ROP state.

`rop_pass_split` is enabled only for the Arm driver reporting MaliSX2 0.2.3.
Legacy passes also explicitly synchronize attachment stores with later loads
and blending when the layout does not change. No query capture, per-draw
readback, frame wait or title-specific setting is required. For diagnosis,
`debug.hakux.quirks=-rop_pass_split` disables the workaround; clear it to
restore driver defaults. All temporary pass-splitting experiments were removed.

```sh
cmake -S tests/native/rop_pass -B build/rop-pass-host
cmake --build build/rop-pass-host --config Debug
ctest --test-dir build/rop-pass-host -C Debug --output-on-failure
```

### Frame rate limit

Settings > Frame rate limit offers no limit, 30, 60, 90 and 120 FPS. This is
a global upper bound independent of the game's vblank/IMMEDIATE choice and
the existing uncapped-vblank switch. It applies at the next game start. The
front-end SWAP producer waits between frames, publishing prior draws before
sleeping; the renderer can finish them without queuing extra frames behind
a throttled presenter. Stalls and pauses do not accumulate catch-up frames.
Games whose own limit is 30 or 60 FPS retain that lower rate.

The RG477M installation was configured to 120 FPS. Serious Sam measured
about 118 FPS in gameplay after previously running at 130-200 FPS. Source
video is still limited by its own frame rate. Block artifacts in the tested
Spider-Man attract XMV were also present when the original WMV2 640x480
stream was decoded outside the emulator; that comparison does not establish
the quality of every cinematic in the game.

### Release package and HUD

The current RG477M build is `1.2.0-rg477m.1` (version code 9), labelled
`hakuX RG477M`. It uses the release build type with R8 optimization and
`debuggable=false`. The HUD retains FPS and average/last frame time. The
debug diagnostic rows are disabled by default and absent from release.

Launcher artwork was supplied as `691172.png` and is preserved unchanged in
`android/artwork/rg477m-launcher-source.png`. Legacy, adaptive and monochrome

`python3 tools/native/generate-rg477m-icons.py` (Pillow required for this

For an in-place update of the existing local installation, the packaged
release uses `-PhakuxApplicationId=com.rfandango.haku_x.debug` and the same
local signing certificate as the previous APK. The `.debug` package suffix
is retained for update compatibility; it does not make this release debuggable.
This is an unofficial device adaptation, not an upstream signed release.
Keep the local keystore private and preserve it for future updates.

```sh
cd android
./gradlew -PhakuxApplicationId=com.rfandango.haku_x.debug assembleRelease testReleaseUnitTest
```

Configure release signing with local `key.properties` (not distributed), or
align and sign the unsigned release APK externally with the existing key.
Installing with `adb install -r` retains game storage permissions, imported
MaliSX2, HDD images and preferences. A fresh installation requires first-run
setup and driver import as below; the 120 FPS limit is a stored device setting.

### Android build

Start with a Git checkout of the pinned hakuX commit and apply the supplied
patch, or use a Git checkout containing these sources. Follow
[README.md](README.md) for the Android toolchain, FEX submodule and native
dependencies. The source ZIP alone does not contain FEX or third-party build
dependencies; it is not a self-contained/offline build tree.

The native build **must** include `NC_DEPS/adrenotools` at the pin above,
including its submodules. Confirm that CMake builds `hakuxcore` with
`NC_ADRENOTOOLS=1`. Copy the newly built native core, SDL3 and all four hook
libraries into `jniLibs` with `tools/native/app-libs.sh` before building the
APK. Packaging an older prebuilt core will omit the fence compatibility path.

1. Install the newly built debug APK on RG477M (separate debug application ID).
2. Open Settings → GPU driver → Add a driver.
3. Select the unmodified official MaliSX2 ZIP named above. It contains
   `meta.json` and `libvulkan_malisx2.so` at its root. No repackaging is needed.
4. Start a game from a fresh boot at the existing default **1× resolution**,
   automatic aspect ratio and normal game frame-rate limit. Increase resolution
   only after checking stability and frame times on the device.
5. Confirm logs include both `MaliSX2 active: ...malisx2...` and
   `GPU completion: ordered Vulkan fences (MaliSX2 compatible)`.

To revert, select **System driver** and restart the game. Do not install Turnip
on RG477M. This integration does not replace the phone's system GPU driver.

## Host verification

The tests compile the actual production `timeline.c` against controllable
Vulkan and host doubles. They do not establish real GPU, shader or WSI behavior.

```sh
git clone --depth 1 --branch v1.4.304 https://github.com/KhronosGroup/Vulkan-Headers.git ../Vulkan-Headers
cmake -S tests/native/timeline -B build/timeline-host -DVULKAN_HEADERS=/absolute/path/to/Vulkan-Headers
cmake --build build/timeline-host --config Debug
ctest --test-dir build/timeline-host -C Debug --output-on-failure
```

Eight cases cover ordered/merged completion and guest readback, ring wrap,
back pressure, loss with blocked producer and CPU waiter, submit/reset/create
failures, and the existing native timeline path.

Standalone Kotlin policy test (no Android SDK needed):

```sh
kotlinc android/app/src/main/java/com/rfandango/haku_x/GpuDriverPolicy.kt \
  tests/android/DriverPolicySmoke.kt -include-runtime -d build/driver-policy-tests.jar

```

For an on-device comparison, `adb shell setprop debug.hakux.caps -timeline`
forces the fence path on a timeline-capable driver; clear the property after
testing with `adb shell setprop debug.hakux.caps ''`.
